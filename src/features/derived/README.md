# features/derived

Derived signals of D-070 (catalog section 5), computed on rt-core. **Part 1: class A signals whose inputs are DIDs or other computed derived signals. Part 2a: the class-B ride summaries that are scalars over DIDs and computed signals (section "Rides").** Everything else (signals with sensor/IMU/GPS inputs, the events other than `stop_event`, binned, per-gear and window-record signals) is reported NOT_COMPUTED with a reason. No bus output, no VSS, no UDS DID (D-070 item 4: log only; the ride-summary DIDs 0xFD40-0xFD49 are part 2b and need their byte layouts in defs first). Class-A outputs sit in a static table read by `derived_get()`, ride summaries are read by `derived_ride_get()`; the future logger reads them.

**QM information (D-070 item 5).** It never feeds 0x020, safety-node, the heartbeat or the anomaly safety net. CI greps that `features/cornering`, `features/heartbeat`, `features/uds`, `features/vehicle_republish`, `services/` and `app/comms` never include `features/derived/` (the comms task only calls `services/derived_inputs`).

## Files

| File | What |
|---|---|
| `derived_core.{h,c}` | Pure core (no HAL, RTOS, services, clock): input array in, output table out. Float32, `isfinite` checks, `-fno-math-errno`, refuses `-ffast-math`. |
| `derived_types.h` | Flags, status, input/output rows, the epoch and the ride selector shared by the core and the ride module. |
| `derived_ride.{h,c}` | Pure class-B accumulators and closed values (part 2a). |
| `derived_gear.{h,c}` | Gear estimate from the measured ratio, pure and private to this feature for now; it moves to `services/` when a second feature needs a gear (architecture-guard). |
| `derived.{h,c}` | Glue of the derived task: reads `services/derived_inputs`, maps it to the core's inputs, steps the core, `derived_get(sig, &out)`. |
| `../../services/derived_inputs.{h,c}` | The comms task to derived task hand-over (below). |

## Rides (class B, part 2a; D-070 parts 2-3, D-087 item 2)

A ride is one D-075 stop epoch of the vehicle tester. `services/tester_epoch` carries `{open, counter}`: the UDS client glue (comms task) sets it after every client step from `uds_client_core_epoch()` (the client core bumps its counter where an epoch opens and clears `open` where the ECU goes absent), and `derived_inputs_publish()` copies the two fields into the SAME snapshot record as the DIDs; the derived task never reads the client and the core never duplicates `ecu_absent_timeout_ms`.

- **Detection.** `derived_core_step_epoch()` closes the open ride when the counter differs (`!=`: any jump size, wrap-safe) or `open` is false, then opens a new one if an epoch is open. Close + reopen in one record (counter + 1, `open` still true), a jump by more than 1, the uint16 wrap and open -> false -> true are unit-tested. The record of the step that closes a ride is never added to it.
- **Fresh state.** A new ride resets the class-A state to ride-local (grids anchored at the ride's first samples, integrals, windows, the altitude reference, the stop event) and ignores the DID samples the core already holds (the old epoch's, equal stamps) until a new sample arrives, like the reference evaluating every ride on its own. Without an epoch (`derived_core_step()`, or `known == false`) there is no ride and class A runs as in part 1.
- **Computed set (12, from the gen table: class B, `rt_core_ready`, scalar, inputs only DIDs or computed signals, a formula in `derived_ride.c`; the golden vectors have the same 12):** `ride_distance`, `ride_time`, `ride_idle_time` (last valid class-A output of the ride), `ride_stop_count` (valid stop events), `ride_fuel_used` (time integral of the fuel rate, a sample held until the next one but never beyond that DID's own `stale_after_ms`, D-087; the segment still open at the close adds nothing, like the reference), `ride_fuel_consumption` (used / distance x 100; no distance is STANDSTILL), `ride_ltft_mean`, `ride_stft_std` (population, Welford), `ride_coolant_rate_max`, `ride_start_coolant_temp`, `ride_end_coolant_temp`, `ride_start_intake_temp` (first / last DID sample of the ride). The accumulators of the integral and the means are `double` (small increments over a long ride), results float32 through the gen range check (outside it: OUT_OF_RANGE, never clamped).
- **Not computed, with a reason:** binned and per-gear signals (`operating_point_time`, the time-at-temperature histograms, `ride_final_drive_ratio`: reason ELEMENTS), signals with sensor inputs or inputs that are not computed (GPS, bus health, tester health, heat soak, ...: NO_FORMULA / NOT_READY), the W1-W5 window records (NO_FORMULA: the window state machine is not implemented) and the rest of class B.
- **Output.** `derived_ride_get(CURRENT | PREVIOUS, sig, &out)` (derived task only): CURRENT is the open ride as it would close now, PREVIOUS the last closed ride (one record, replaced at the next close); NO_DATA while there is none. No UDS DID (part 2b), no CAN, no persistence: **a power-down close is out of 2a** (D-045 logging comes later), so a ride that ends with the power loses its summary; the epoch flag and counter are the only ride signal.
- **Memory.** Running state plus the closed record only for the computed signals: `derived_ride_t` is in `derived_core_t` (see Memory).

## Task placement and the cross-task input

`services/vehicle_signals` is single-task (the UDS client writes it in the comms task), so the derived task never reads it. `derived_inputs_publish(now)` runs once per pass in `comms_pass()` as the last call, after `uds_server_step()` (nothing later writes `vehicle_signals`, and no frame work waits for the copy): one bounded pass over the 40 DIDs copies {value, sample stamp, state} into a `services/snapshot` (three static slots, initialised INVALID before either task starts). `derived_step()` is the one consumer call site and copies the whole record out in the same call (snapshot second-reader rule). The record carries a pass counter; `test_derived_inputs_stress` (ASan/UBSan and TSan) shows a record is never torn. Entries keep the sample's own stamp, so a stalled comms task makes every output stale by the signals' own limits.

The derived task runs below the EKF and below the comms task (CLAUDE.md rule 4, D-070 item 5): no blocking, no lock, static memory, every loop bounded by a compile-time size. In the host program it is stepped from the main loop after `comms_pass()`. The H7 task wiring comes with the H7 port. `derived_step()` and `derived_get()` are for the derived task only; a future logger runs in that task or gets its own snapshot of the output table.

## Rules (the reference engine: vehicle-server `derived/engine.py`, `context.py`)

- **Computed set** is decided at init from the gen table (class A, `rt_core_ready`, inputs only DIDs or computed derived signals with a lower index, a formula in the dispatch switch, windows that fit the sample buffers). It is not a hand-written list of 28: `test_derived_core` checks that it equals the set in the golden vectors (28 = 27 point/integral signals + `stop_event`; no difference). Evaluation order is the gen index order; a test asserts every derived input comes earlier.
- **Sample-and-hold with age.** A value is usable while `age <= stale_after_ms` (age equal to the limit is fresh, one more is stale, like the reference). The limit is the DID's own `stale_after_ms` from `vehicle_cl250_dids[]` for a DID input (D-070; e.g. 300 ms for the speed even where a signal's own limit is 330) and the producer's `stale_after_ms` for a derived input. The glue passes the sample stamp and the core applies that limit, the same one `vehicle_signals` uses for its STALE. Every DID input is judged this way, the event signal `stop_event` and (later) the class-B summaries included (D-087 item 1); the reference's 3-poll age is gone. A sample counts as lapsed when older than the longest limit and stays unusable until a new sample (a wrapped counter can not revive it).
- **Grid.** Each signal has a `period_ms` grid that starts at the latest first-sample time of its inputs (a derived input: the producer's start). A step evaluates the latest due tick of a signal (no catch-up) and stamps the output with the tick. Called every ms (tests) it is the reference exactly; called every few ms it is up to one step late.
- **Range, never clamped.** A result outside the gen `[min, max]` is invalid with OUT_OF_RANGE (the unranged value is kept for diagnostics). A non-finite input or result is MATH_ERROR (the reference reports a non-finite result as out_of_range; its inputs can not be NaN).
- **Flags** are the reference's, in the reference's input order (STALE, INVALID_INPUT, INSUFFICIENT_SAMPLES, STANDSTILL, NO_CONSUMPTION, NO_POWER, ENGINE_OFF). Every input read must be declared in the signal's gen inputs, else MATH_ERROR (fail closed).
- **Windows** (acceleration, jerk, fuel average, coolant and oil rate): fixed ring buffers per DID or derived producer, sized at compile time. gen/ exports window and period only as table data, not constant expressions, so a `_Static_assert` can not derive the capacity; instead `DERIVED_WIN_*_CAP` are named constants checked against the gen table at init (`window_ms / poll period + 2`): a window that does not fit makes its signal NOT_COMPUTED (reason SIZING), never silently truncated, and a test asserts none does.
- **Integrals** (trip distance, trip time, idle time) follow the reference's hold rule: a value is held from a sample until the next sample but never longer than the shortest remaining freshness of its inputs, so a gap adds nothing. The accumulators are `double` (a long ride would lose small increments in float32); the M7 has a double-precision FPU.
- **`stop_event`** is not on a grid: one row per stop at the time the vehicle moves off (value = duration in s, the reference's rule: speed 0 after moving, engine running, a gap longer than the speed DID's own `stale_after_ms` ends it; the engine must have a fresh RPM by that DID's own limit).

## Tests

- `test_derived_core`: golden replay of the four scenarios (10 801 rows, stepped every ms): grid time, valid flag and flag code exact, values within the per-signal tolerance (resolution / 2), equal counts of rows and core evaluations, event rows; zero rows needed the boundary allowance (the rule is documented at the top of the test; the skip list is asserted empty). Plus hand-computed unit tests (torque and power, air density and altitude, fuel formulas, residuals, gearbox ratio and gear, zero-guard flags, window slope and mean, integrals across a gap, the stop event and its gap rule, staleness at the limit and one past, range without clamping, NaN/inf, lapse, late steps, coarse stepping on the grid, not-computed reasons, dependency order, computed set = golden set) and the pinned-gen check below.
- **Vectors vs the pinned gen table.** The expected outputs depend on the gen table the vectors were generated from. `test_vectors_match_the_pinned_gen_table` hashes (FNV-1a) everything of gen/ they depend on (period, stale limit, window, range, resolution and inputs of every vector signal, the poll period of every DID read, and the twelve vehicle constants the generator uses) and compares it with the value recorded in the test; it also checks `abs_tol == resolution / 2` and that inputs follow the poll periods. A defs bump that changes any of them fails this test with "regenerate the vectors", not with unrelated value differences. The vectors' banner names the defs version they were generated from; this test, not that banner, decides whether the pinned table still matches.
- `test_derived_ride`: the class-B golden vectors (five scenarios incl. `two_rides`, the rides table driving the epoch; 72 closed values, valid flag and flag exact, values within resolution / 2; the vectors have no sensor or GPS input), the computed set = the golden set (12), the not-computed reasons, the epoch cases above and the accumulators (fuel integral across a gap, trim mean / std, range, NaN). `test_uds_client_core` / `test_uds_client` check the epoch counter and the glue's `tester_epoch`.
- `test_derived_gear`, `test_derived_inputs`, `test_derived` (glue), `test_derived_inputs_stress` (two threads, TSan too).

## Memory (D-070 item 6)

Static RAM with the ride summaries (part 2a), measured with `arm-none-eabi-size` on the M7 release build: **about 13.9 KB** (`derived.c` 12 388 B = the core with its tables, sample buffers and ride state, the 40 inputs and the newest record; `derived_inputs.c` 1 493 B = three snapshot slots with the epoch fields; `tester_epoch.c` 4 B; host `sizeof(derived_core_t)` 12 592 B). The ride summaries add about 0.7 KB to part 1's 13.2 KB (12 closed-record rows and the accumulators). That is **over D-070's estimate of at most about 10 KB for all signals**, already for 28 of them: the 60 s fuel-consumption window keeps 547 speed samples (4.4 KB), the biggest single block, and the per-signal tables over all 141 gen indices take 5.6 KB (host). Recorded here per D-070 item 6; trimming options are a shorter window or a running-sum average, and a table over the computed signals only. When the H7 linker script lands, this block must stay out of the EKF's DTCM.

## Cost (D-070 item 6)

Numbers are in the PR description. The target WCET comes with the board; the host numbers are only a relative guide. Bounded work per step: one pass over 40 DIDs, one over the gen table, at most one evaluation per computed signal plus three integral updates, every window loop limited by its buffer (the largest, the 60 s fuel average, is 548 speed samples).
